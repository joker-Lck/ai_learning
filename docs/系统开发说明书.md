# 第一部分 需求分析

## 1.1 项目背景与问题提出

### 政策背景

教育部《教育信息化2.0行动计划》明确提出"以信息化引领构建以学习者为中心的全新教育生态"。《新一代人工智能发展规划》将"智能教育"列为重点应用，要求利用 AI 技术实现因材施教、个性化学习。2024年以来，大语言模型（LLM）技术的成熟为教育领域的智能化应用提供了前所未有的技术基础。

### 现实痛点

| 痛点 | 表现 | 影响 |
|------|------|------|
| **资源碎片化** | 学习资料散落在教材、网课、笔记等多个渠道 | 学习效率低，知识体系不完整 |
| **缺乏个性化** | 通用资源无法适配个人知识基础和认知风格 | 薄弱环节得不到针对性强化 |
| **学习路径盲目** | 不知道先学什么、后学什么，缺乏系统规划 | 知识断层，前后置依赖关系混乱 |
| **反馈滞后** | 考试后才知道薄弱点，缺乏过程性评估 | 错失最佳干预时机 |
| **答疑不便** | 课后遇到问题难以及时获得专业解答 | 问题积累，学习信心下降 |

## 1.2 需求调研与用户画像

### 调研方法

- **问卷调查**：200+ 名在校大学生，覆盖计算机科学、软件工程、数据科学等专业
- **深度访谈**：15 名不同年级学生一对一对话
- **文献分析**：30+ 篇教育技术领域论文
- **竞品分析**：10+ 款学习工具功能对比

### 核心需求

| R6 | 知识库管理 | 上传资料构建 RAG 知识库 | P1 |

### 用户画像

| 类型 | 特征 | 核心诉求 |
|------|------|---------|
| **自主学习型** | 主动性强，有明确目标 | 高效路径 + 深度资源 |
| **查漏补缺型** | 有薄弱科目 | 错题管理 + 专项练习 |
| **考前突击型** | 时间紧迫 | 学习计划 + 重点推荐 |

# 第三部分 核心算法

## 3.1 AI 模型路由

**源文件**：`services/spark_client.py`

| 模型 | 用途 | 说明 |
|------|------|------|
| mimo-v2.5-pro | 文本对话/推理（主力模型） | 支持 reasoning_content 思考链 |
| mimo-v2.5 | 视觉理解（图片多模态） | 支持 chat_with_image |
| mimo-image | 图片生成 | generate_image |
| mimo-ocr | 文字识别 | ocr_image |
| mimo-tts | 语音合成 | text_to_speech |

MiMo-v2.5-pro 是推理模型，回答分两部分：
- `reasoning_content`：推理过程（思考链）
- `content`：最终答案

**提取策略**：优先 content → 空则从 reasoning_content 提取 → JSON → 定义性句子

## 3.2 混合检索系统

**源文件**：`data/rag_knowledge_base.py`

系统采用三路混合检索，兼顾语义相似度和关键词精确匹配：

### 3.2.1 KNN 关键词检索

SQLite FTS5 全文索引精确匹配，适合专业术语、公式、代码。使用 `CREATE VIRTUAL TABLE ... USING fts5(tokenize='unicode61')` 创建，配合同步触发器维护索引。

### 3.2.2 ANN 向量检索

**源文件**：`data/embedding_service.py`

FAISS `IndexFlatIP` 内积搜索（归一化后等价余弦相似度），理解语义相近表达。

#### Embedding 技术方案

系统采用 **TF-IDF + SVD** 本地向量化方案，无需外部 API 和网络依赖：

| 参数 | 说明 |
|------|------|
| 分词工具 | jieba（中文分词） |
| 向量化方法 | TF-IDF（词频-逆文档频率） |
| 降维方法 | SVD（奇异值分解） |
| 向量维度 | 动态计算（50-200维，取决于语料规模） |
| 文本截断 | 最大 8000 字符 |
| 相似度计算 | 余弦相似度（L2归一化后内积） |

#### 训练流程

应用启动时自动训练 embedding 模型：

1. **加载语料**：从 `data/corpus/education_corpus.txt` 和知识库文档加载训练语料
2. **构建词表**：使用 jieba 分词，统计词频，构建 TF-IDF 词表
3. **SVD 降维**：对 TF-IDF 矩阵进行 SVD 分解，得到低维向量表示
4. **模型缓存**：训练完成后缓存在内存中，供后续检索使用

#### 性能指标

| 指标 | 值 |
|------|------|
| 训练时间 | <1秒（82条语料） |
| 检索延迟 | ~5ms（单次查询） |
| 内存占用 | ~10MB（词表+模型） |

### 3.2.3 RRF 融合排序

```python
RRF_score(d) = Σ 1/(k + rank_i(d))    # k=60
```

KNN 结果 + ANN 结果 → RRF 统一排序 → Top-N 返回。

### 3.2.4 三级回退策略

| 级别 | 触发条件 | 检索方式 | 响应时间 |
|------|---------|---------|---------|
| L1 | FAISS 就绪 | IndexFlatIP 搜索 | ~5ms |
| L2 | FAISS 可用但索引为空 | 惰性构建后搜索 | ~500ms（首次） |
| L3 | FAISS 不可用 | 暴力余弦 KNN | ~100ms |

## 3.3 高级检索方法（2023-2026）

**源文件**：`services/advanced_retrieval_service.py`

系统实现了 11 种前沿检索策略，通过 `smart_search()` 统一入口按策略路由：

### (1) HyDE — 假设性文档嵌入（Gao et al., 2023）

```
用户问题 → LLM 生成假设答案(200-400字) → 向量化 → FAISS 检索
```

- **优势**：零侵入，仅改变查询端
- **适用**：短查询、概念性问题

### (2) Multi-Query — 多查询检索（LangChain, 2023）

```
"梯度下降原理" → LLM 改写为 3-5 个变体 → 分别检索 → 合并去重
```

- **优势**：提高召回率，捕捉单一查询遗漏的文档

### (3) RAG-Fusion + RRF（Raudaschl, 2023）

多查询 + Reciprocal Rank Fusion 加权融合，是当前 RAG 社区最佳实践。

### (4) Contextual Retrieval（Anthropic, 2024）

为每个 chunk 生成上下文前缀后再嵌入，检索失败率降低 35%。

```
原始: "反向传播通过链式法则计算梯度"
添加上下文后: "[来自《机器学习》第5章·神经网络训练] 反向传播通过链式法则计算梯度"
```

### (5) Graph-Enhanced RAG（Microsoft GraphRAG, 2024）

```
"梯度下降" → 图谱查找 → [学习率, 损失函数, 梯度爆炸]
→ 扩展查询检索 → 结合图谱关系给出结构化答案
```

### (6) ReAct 推理-检索交替（v8.0 新增）

```
LLM 推理 → 判断需要什么信息 → 检索 → 继续推理 → 检索 → ... → 综合答案
```

- **优势**：推理与检索交替执行，每步针对性检索
- **适用**：推导题、多步骤答疑、理科推导

### (7) 语义缓存（v8.0 新增）

```
新查询 → 计算 embedding → 与缓存 embedding 算余弦相似度
       → 相似度 > 0.92 → 直接返回缓存结果
       → 相似度 < 0.92 → 正常检索 → 结果写入缓存
```

- **优势**：相似问题复用结果，减少 API 调用 30-50%

### (8) Self-RAG 检索决策（v8.0 新增）

```
问题 → retrieval_gate（是否需要检索？）
     → 不需要 → 直接回答
     → 需要 → strategy_router（按题型选策略）
            → 检索 → result_verifier（质量足够？）
                    → 不足 → 重试新策略
                    → 足够 → 返回结果
```

### 策略路由（13 种）

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| `auto` | 自动选择（短查询用 HyDE，长查询用 RAG-Fusion） | 默认 |
| `knn` | KNN 关键词检索（SQLite FTS5 精确匹配） | 专业术语、公式 |
| `ann` | ANN 向量检索（FAISS 语义匹配） | 模糊语义查询 |
| `hybrid` | KNN + ANN + RRF 混合（基座策略） | 通用推荐 |
| `hyde` | 假设性文档嵌入（2023） | 短查询、概念性问题 |
| `multi_query` | 多查询检索（2023） | 提高召回率 |
| `rag_fusion` | RAG-Fusion + RRF（2023） | 通用推荐 |
| `contextual` | 上下文精排（2024） | 高精度场景 |
| `graph` | 图谱增强检索（2024） | 有图谱数据时 |
| `multi_hop` | 多跳推理检索（逻辑图 + 2-5跳探索） | 复杂推理问题 |
| `react` | ReAct 推理-检索交替（v8.0 新增） | 推导题、多步骤问题 |
| `hybrid_advl` | 基座 + HyDE + RAG-Fusion 三路 RRF | 平衡速度与精度 |
| `ensemble` | 全部 6 种方法取并集，RRF 融合 | 最全面 |

## 3.4 无限长时记忆架构

**源文件**：`services/memory_service.py`

### 四层记忆模型

| 层 | 存储 | 生命周期 | 容量 |
|----|------|---------|------|
| 短期记忆 | `short_term_memory` | 会话内 | 最近 50 条 |
| 情景记忆 | `episodic_memory` | 长期衰减 | 无限 |
| 语义记忆 | `semantic_memory` | 长期 | 无限 |
| 实体记忆 | `entity_memory` + `entity_relations` | 长期 | 无限 |

### 遗忘机制（艾宾浩斯曲线）

```
R = e^(-t/S)
R: 保留率, t: 距上次访问天数, S: 稳定性 = max(1, access_count × 2)
```

访问越多 → 稳定性越高 → 衰减越慢。重要性 < 0.2 自动标记遗忘。

### 记忆增强问答

```
用户提问 → 检索语义/情景/实体记忆 → 构建增强 Prompt → AI 回答 → 保存新记忆
```

## 3.7 反思验证器 (Reflector)

**源文件**：`services/reflector.py`

对 AI 生成的答案进行质量评估和验证：

- **答案质量评分**（0-10）：准确性、完整性、相关性、逻辑性四维度评估
- **证据链检查**：关键声明是否有上下文支撑，置信度阈值 0.5
- **自动改进**：低分（<6）触发二次检索（ensemble 策略）+ 重新生成，最多重试 2 次
- **降级策略**：AI 评分失败时降级到规则评分（长度、关键词匹配）

## 3.8 多跳推理检索 (Multi-Hop Retriever)

## 附录E：版本变更清单

### v8.1.0 (2026-07-19) — 用户体验全面升级

**新增功能**：
- 今日建议升级为专业学习规划师（多维薄弱点分析+遗忘曲线复习+认知风格策略）
- 智能提醒系统（GET /review-due + /review-reminder）
- 成绩趋势折线图（Recharts LineChart）
- 资源类型智能推荐（根据学科关键词自动勾选）
- AI 追问按钮（辅导回答下方再解释/举例子/换角度）
- 新用户引导流程（首次访问3步引导遮罩）
- 学习路径→资源生成联动（一键生成配套资源）
- 番茄钟计时器（可自定义专注/休息时长）
- 错题录入优化（两步式极简表单+拍照识别入口）
- 工作台布局重构（今日建议横置4宫格）
- PDF解析增强（支持扫描版电子书AI OCR识别）
- RAG存储容量提升（50万字符+2000段落）

### v8.0.0 (2026-07-17) — 检索系统全面升级 + 协同学习

**新增功能**：
- 语义缓存（相似问题复用结果）
- 检索评测系统（NDCG/MRR/Recall）
- Multi-Hop可视化（推理链路展示）
- FAISS索引自适应（按文档量自动选择索引类型）
- Self-RAG检索决策（三层决策：是否需要检索→选策略→校验质量）
- ReAct推理-检索交替
- 智能路由（按题型自动分发策略）
- Agent协作实时可视化（SSE推送）
- 协同学习小组（创建/加入/资源共享/互评/进度对比）
- 增强视觉识别（图像预处理+多策略OCR）
